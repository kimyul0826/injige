# 추론 재실행 없는 성능 개선 실험 (Llama-3-8B V2 응답 재사용)

- 입력: `outputs/llama3-table1-upstream-v2`의 저장 응답 3,000개 (1,000문제 × standard/CoT/RePE). **새 모델 추론 0회.**
- 모든 생성 파일은 `exp/claude/` 안에만 있음. 프로젝트 코드·결과는 읽기만 함 (`PYTHONDONTWRITEBYTECODE=1`).
- 재현 검증: 하네스의 `official` 변형과 A*(w=1)가 저장된 V2의 operation/storage/length와 **3,000건 + A* 1,000건 모두 정확히 일치**함. LLM 단독 raw 경로와 유효성도 1,000×3건 모두 일치함. 불일치가 하나라도 있으면 assert로 중단되도록 함.
- 지표: A* 대비 비율의 기하평균 ×100 (논문 정의).
  - "공정 비교": A*에도 같은 구현 변경(중복 pop 제거, tie-break)을 적용한 기준값을 씀.
  - "vs 공식 A*": 저장된 공식 A*를 분모로 둔 값.

## 0. 핵심 결론

1. **LLM 없는 weighted A\*가 기준선이 되어야 함.**
   - 공식 LLM-A*에서 waypoint가 없으면 f = g + 2·h가 됨. 즉 weighted A*(w=2)와 같음.
   - weighted A*(w=2): 탐색량 34.32 / 경로 길이 102.02. 공식 LLM-A*(45.55–63.95 / 102.5)보다 둘 다 좋음.
2. **효율 지표만 보면, 탐색·waypoint를 고쳐 얻는 이득은 대부분 "weighted A\*에 가까워지는 것"임.**
   - 35개 LLM-A* 변형을 돌렸고, 그중 weighted A* 곡선(같은 경로 길이에서의 탐색량)보다 아래에 오는 것은 0개.
   - 가장 근접한 것은 `progress 전환 + wg1.5/wt0.5`로, 곡선보다 +0.5–0.7%p 위.
3. **실질적인 개선은 세 군데에서 나옴.**
   - (a) **target 전환 규칙 (`switch_progress`):** 공식 대비 탐색량 −21~−45%. A* 2배를 넘는 폭주가 40/50/124건에서 3/3/3건으로 줄어듦.
   - (b) **LLM 단독 후처리 (`snap+pull`):** 유효 경로율 12.7/11.4/10.5%에서 17.1/17.0/27.0%로 오름. 3응답 앙상블은 38.9%.
   - (c) **유효성 게이트 (§4):** LLM 경로가 충돌 없을 때만 LLM 안내를 쓰면 weighted A*보다 탐색량이 약 1% 적고 경로도 같거나 짧음. 95% CI가 100을 넘지 않음(standard/CoT). 맵을 짝수/홀수로 나눈 양쪽에서도 같은 방향.
4. **오라클 상한:** 문제마다 LLM 사용 여부를 완벽하게 고르면 weighted A* 대비 탐색량 −8%. 개선 알고리즘이 노릴 수 있는 여지는 "언제 LLM을 쓸지 고르는 기준"에 있음.

### 해석
- **target 전환 규칙이 공식 LLM-A\*의 가장 큰 결함임.**
  - 공식 코드는 이웃이 target과 같은 좌표일 때만 전환함. target이 벽 너머에 있거나 이미 지나쳤으면 계속 그쪽으로 끌려감.
  - `progress`는 "현재 노드가 target보다 goal에 가까우면 그 target을 버림"이라는 한 줄 규칙. 폭주 사례(최대 16배)를 약 3배 이내로 묶음.
- **snap/clamp는 오히려 나쁨.** LLM이 지도 밖에 찍은 점은 대개 의미 없는 점임. 살리는 것보다 버리는 편이 나음.
- **우회 waypoint 제거(prune)는 RePE에서만 효과가 큼.** RePE가 불필요한 우회점을 많이 만들기 때문.
- **target 항 가중치 wt를 낮추고 goal 항 가중치 wg를 높이는 것이 weighted A\*에 가장 가까운 설정임.** 결국 LLM 안내를 약하게 쓸수록 좋아짐. Llama waypoint의 품질이 낮다는 뜻.
- **문제별로 보면 LLM 안내가 이기는 문제도 있음.** `s:wg2_wt0.5` vs weighted A*(w=2), 탐색량과 길이 모두 고려:
  - standard: LLM 우세 322 / 열세 269 / 맞바꿈 409.
  - RePE: 287 / 343 / 370.

## 5. 주의 사항
- **사후 탐색:** 여러 변형과 임계값(β, timeout, 가중치)을 같은 데이터에서 골랐음. 맵 절반 분할로 방향만 확인함. GPT-4o mini 응답이나 비공개 지도로 다시 검증해야 함.
- **모델·데이터 한정:** Llama-3-8B의 waypoint 품질에 의존하는 결론임. GPT-4o mini waypoint가 더 정확하면 LLM 기여(곡선 대비 차이)가 음수가 될 수 있음. 같은 하네스로 응답만 바꿔 돌리면 됨.
- **집계 방식 차이:** operation은 heap pop 수, storage는 g 딕셔너리 크기. 중복 제거나 tie-break를 바꾸면 A*도 함께 바뀌므로 공정 비교 열을 기준으로 봐야 함.
- **시각화 생략:** 실행 환경에 matplotlib이 없어 Pareto 그림은 만들지 않음. 설치는 하지 않았음. 수치는 `results/*.csv`에 있음.
